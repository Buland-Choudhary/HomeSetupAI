## Theme
> Agents are leaving the chatbox. Build an agent for a place people already work, talk, or live, then make it meaningfully more useful because of that context. Put it into the web, mobile, Slack, Teams, messaging, browsers, voice, wearables, robotics, or somewhere nobody expects to find one yet. What becomes possible when the agent shows up where the work is already happening?

Example places a project might live:
- **At work:** Slack, Teams, email, documents, calendars, tickets, support, live collaboration
- **In your pocket:** messaging, mobile, notifications, short asynchronous moments
- **On the web:** browsers and software where an agent can research, navigate, transact, or take action
- **In the room:** voice, vision, wearables, robotics, other physical-world interfaces

2. **Written description** — what you built, who it is for, and why the context matters
3. **Public GitHub repository** — working code that can be reviewed and learned from
4. **Two-minute demo video** — concise demo of the project in action
5. **Social media post** about the project **tagging the event sponsors/partners**

Submit by the deadline shown in the portal. "A sharp, working demo beats a broad concept."

## Build rules / eligibility
- Any tech stack allowed. Don't need to use every sponsor tool — pick what makes the idea better.
- Project must be a **net-new build created during the official hackathon period**.
- Existing templates, reusable components, libraries, prompts, starter code are OK — but the submitted project and its **core functionality must be built during the event**.
- A pre-existing project cannot be resubmitted or extended as a new entry.
- Teams should be prepared to **explain which parts were created during the hackathon**.
- Goal: a working prototype demo-able by end of day. Keep scope tight, prioritize the core interaction, make the agent's environment essential.
- Starter repo / sponsor resources / credits were to be added to the handbook; **not present at capture time** (credits page needs sign-in).

## Judging criteria (global, each scored 1–5)

### 1. Core Requirements & Functionality
Does the project deliver a working agent inside a place where people already work, talk, or live? Does the core workflow function end to end?
- 1: Doesn't run / no functional agent
- 2: Parts run, but core workflow or environment integration incomplete
- 3: Basic end-to-end agent works in the intended environment, with limitations/bugs
- 4: Works reliably, complete agent experience, minor issues only
- 5: Robust, reliable, fully functional within its intended environment

### 2. Innovation & Theme Alignment
Does the project explore a compelling new place or interaction for agents? Does the environment materially improve what the agent can do?
- 1: Essentially a generic chatbot/automation; environment irrelevant
- 2: Eligible environment, but it's mostly a wrapper
- 3: Clearly addresses theme; environment adds meaningful value
- 4: Environment shapes the core workflow and enables an original agent experience
- 5: Reveals a surprising new agent pattern whose central value **could not be reproduced in a standalone chatbox**

### 3. Technical Execution & Integration
Code, architecture, reliability, tool use, data handling, depth of integration with the environment.
- 1: Little/no execution; conceptual or mocked
- 2: Basic, unstable, or superficial integrations
- 3: Solid execution and working integrations, some rough edges
- 4: Well engineered, reliable, integrates tools/data/environment effectively
- 5: Exceptional engineering — **robust orchestration, thoughtful failure handling, deeply integrated architecture**

### 4. Usefulness & Agentic Experience
Clear value for intended users? Agent intuitive, effective, appropriate for its environment?
- 1: Unclear use case, little value
- 2: Recognizable use case but agent contribution limited / basic prompt-response
- 3: Useful, understandable, agent performs meaningful actions with reasonable user control
- 4: Solves a clear problem; agent feels native to its environment; strong human–AI interaction
- 5: Substantial value via an experience designed specifically for its environment, **using context intelligently while remaining clear and controllable**

## Strategy notes (derived from the rubric)
- The single biggest lever is **Innovation**: the environment must be *load-bearing* — show something impossible in a plain chat window.
- Make the demo path bulletproof (Functionality + Technical Execution); show graceful failure handling and user control/confirmation.
- Record the 2-min video early (before 3:30) — don't leave it for the 30-min submission window.
- Social post must tag sponsors; ensure the GitHub repo is **public** with a clear README.
- Stacking a side-prize sponsor (Ambiguous AI or CopilotKit) meaningfully adds a second shot at a prize.
